Two zones. EVENT LOOP (top) is one thread — only ONE async request runs at a time, the rest wait at an await. THREADPOOL (bottom) is worker threads, where several truly run at once.

Row state

●RUNNING — executing right now
○WAITING — parked at an await
⇢WAITING · worker — a worker thread is running this request's call while its coroutine is parked. Not waiting for a worker — one already has the work. The loop is free, exactly as for any other await. (Calls actually queued for a free thread are counted in the THREADPOOL header)
⋯UNTRACED — the loop is in library code outside your roots, so we cannot see it
✓DONE — finished; stays until you clear

Problems

⏱STALLED — the loop is frozen right now. A long await never trips this
🔥blocking I/O — the loop waited on a file, socket, DNS, database or subprocess. Wrong at any speed, so it shows even for a 3ms call
⚙held the loop — ran too long and we could not see why. Not a verdict, just the fact
